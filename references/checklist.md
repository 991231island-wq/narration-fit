# 人工验收

脚本通过不等于口播能用。交付前看这些：

1. 每一段都能在 HTML 里对上画面说明，没有把下一段的句子提前念完。
2. `trim` 的对照里看得出删了什么（删除线），而不是整段换成另一篇稿。
3. `keep_faster` 的页眉和报告都印着这次实际语速，例如 `5.5`，不是只写「稍快」。
4. 必留句在改后文案里还能读到，并且没有被拆到两段。
5. 未分配区是空的，或者用户明确同意丢掉那些句子。
6. 欠预算的段没有为了填满时间而加水词。
7. 报告里的舒适 4.7、加快 5.5、上限 6.0 仍带着来源标签，没有写成行业标准或真人口播实测。
8. 包内没有视频原片、没有 API Key、没有未授权的他人讲稿。公开发布示例是本 Skill 原创的现代中文。

命令级验收（夹具已在 `examples/`）：

- `demo-fit-trim.json` 在 4.7、`trim` 下退出码 0，每段改后字数 ≤ 预算。
- `demo-fit-keep-faster.json` 在 5.5、`keep_faster` 下退出码 0，报告含本次语速。
- `demo-fit-expand.json` 在 4.7、`expand` 下退出码 0。12 秒发酵段原文明显偏短，改后接近预算且不超过；报告能看出「已扩写」。超预算段标「先修剪」。
- 把过长原文当作改后文案、仍用 4.7 去跑，必须失败。
- 坏时间轴、缺必留句，都必须失败。
- 只改一段再跑，其它段的数字行不变。
